## Summary of Milestone 0 Architecture Decisions

1. **[ADR-001](../ARCHITECTURE_DECISIONS.md#adr-001-logical-page-slotted-b-tree-with-write-ahead-log-oryq-wal-and-mvcc-indirection-map):** Selected a **Logical-Page Slotted B+ Tree (`8192`-byte pages) with Write-Ahead Logging (`.oryq-wal`) and an in-memory `PageVersionIndirectionMap`** over physical Copy-on-Write B+ trees and multi-file LSM trees.
2. **[ADR-002](../ARCHITECTURE_DECISIONS.md#adr-002-oryqdoc-sorted-field-offset-directory--state-normalized-slotted-page-deltas-with-64-bit-bloom-mask):** Selected **`OryqDoc` v1** (8-byte header + 12-byte sorted field-offset directory for $O(\log k)$ zero-copy lookup) paired with **Write-Time State-Normalized Slotted-Page Delta Patches** (`MAX_DELTA_CHAIN = 4`) and a **64-Bit Field-Hash Bloom Bitmask** in each 16-byte slot directory entry, decoupled from physical storage via the pure `RecordCompactor` port.
3. **[ADR-003](../ARCHITECTURE_DECISIONS.md#adr-003-dual-mode-snapshotcoordinator--zero-delay-leader-follower-group-commit):** Selected the **`SnapshotCoordinator`** boundary (default `SingleProcessCoordinator` with a connection-lifetime OS lock, in-process `(st_dev, st_ino)` registry, short admission mutex with reader tokens, and serialized explicit write transactions; post-baseline E2 `SharedShmCoordinator` and E3 queued-command batching).
4. **[ADR-004](../ARCHITECTURE_DECISIONS.md#adr-004-order-preserving-memcomparable-key-encoding--prefix-compressed-compound-indexes-r--16):** Selected **Order-Preserving Memcomparable Key Encoding** (including exact variable-width cross-type numeric ordering), **Prefix-Compressed Compound Index Leaf Pages with $R = 16$ Restart Points**, and the **Single-Array-Per-Compound-Index Guard** (`ORYQ_ERR_PARALLEL_ARRAY_INDEX`).
5. **[ADR-005](../ARCHITECTURE_DECISIONS.md#adr-005-wal-backed-pluggableindex-substrate--compile-time-feature-gates-oryq-fts-oryq-vec):** Selected an `oryq-index`-owned **`IndexProvider` / `IndexStorageContext<'tx>` Substrate** with Two-Tier Pending-Delta B+ Tree batching and Page 0 / catalog `required_write_features` bitmasks to isolate optional `crates/oryq-fts` and `crates/oryq-vec` crates (post-baseline E1) hosted exclusively at `oryq-core` composition.
6. **[ADR-006](../ARCHITECTURE_DECISIONS.md#adr-006-step-unpinning-lending-cursors--dual-path-panic-safe-c-abi-includeoryqh):** Selected **Step-Unpinning Lending Cursors (`OryqDocView<'cursor>`)** and a **Dual-Path Panic-Safe C ABI (`include/oryq.h`)** providing both JSON convenience functions and cursor-scoped zero-copy binary field accessors (`oryq_cursor_get_*`).
7. **[ADR-007](../ARCHITECTURE_DECISIONS.md#adr-007-reviewed-correctness-contracts--baseline-release-scope):** Established reviewed correctness boundaries: baseline M10 release scope with separate E1–E3 extension gates, non-revocable live reader pins, engine fault on uncertain commit sync failure, ordered checkpoint data-before-header sync with redundant WAL reset intent, exact variable-width numeric keys, non-reused `u64` `RecordId` bitmaps, FFI child-handle ownership (`BUSY`), and shared query memory budgets.
8. **[ADR-008](../ARCHITECTURE_DECISIONS.md#adr-008-domain-crates-owner-local-features-and-one-composition-root):** Modularized source ownership into eight baseline domain/adapter crates (`oryq-types`, `oryq-document`, `oryq-engine`, `oryq-index`, `oryq-query`, `oryq-core`, `oryq-ffi`, `oryq-cli`) plus two optional E1 provider crates (`oryq-fts`, `oryq-vec`), with owner-local feature folders/registries and a single composition root in `oryq-core`.
